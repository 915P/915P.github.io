先把最重要的数字放前面：**全量编译 56 秒**。我一开始问 LLM「大概要多久」，它答「约 10 分钟」，实际重建全程 99 秒。真正的大头是装编译依赖，9 分 42 秒，而且是一次性的。这个估算偏差是怎么回事，后面细说。

## 三个都不满意，于是决定自己编

这台机器是 Ubuntu 24.04（Linux Mint 22.3），Intel Arrow Lake-P 核显。想用最新的 VLC 3.0.24，发现三条路全堵：

| 方案 | 问题 |
|---|---|
| apt 官版 | 停在 **3.0.20**（`3.0.20-3build6`），而 VideoLAN 已经发到 **3.0.24** |
| snap 版 | 装上试过，**硬件加速开不起来** |
| 网上的预编译包 | 来源不明的第三方 deb，不敢装 |

于是决定源码编译。但我不想手动踩一遍 `build-dep`、configure 报错、链接失败的坑——整个过程交给了 LLM 编码代理（OpenCode）跑完，我负责定验收标准：**硬解日志要见到实锤、下载文件要对得上官方校验和、装完系统里只能有一个 VLC**。

## 下载源：USTC 居然镜像了 VideoLAN

所有能走 USTC 的都走 USTC（IPv6 教育网出口，快）：

```console
$ curl -o vlc-3.0.24.tar.xz https://ipv6.mirrors.ustc.edu.cn/videolan-ftp/vlc/3.0.24/vlc-3.0.24.tar.xz
27620304 bytes in 8.9s   (3.1 MB/s)
$ sha256sum vlc-3.0.24.tar.xz
e7cab503d1d7d5849b89d2cf0e1ee60d0ef6d012407791b644b9cfc0cc225fdf   ← 与 VideoLAN 官网公布值一致
```

小坑一个：直接 curl 会吃 403——USTC 对默认 User-Agent 拦了一层，换 UA 后又弹一个 JS 验证页，而那个页面要写的 cookie 内容就是**本机 IPv6 地址**（`addr=<IP>`），带上就过了。apt 部分则全程顺利：USTC IPv6 拉 62.4 MB 元数据只用 14 秒。

## 环境：编译放进 Docker，系统一行不碰

方案是容器化：拉一个 `ubuntu:24.04`，把 Ubuntu 官方 vlc 包的全套编译依赖（`apt-get build-dep vlc`，约 300 个包）装进去，源码目录挂载进来编译。好处很直接——**编译阶段完全不需要 root**，产物落在宿主机目录里，装不装、什么时候装由我决定。

这里踩了当天最有教育意义的一个坑：**ubuntu:24.04 基础镜像没有 `ca-certificates`**。apt 走 HTTPS 到 USTC 时证书校验失败，`apt-get update` 却只报 warning 不返回错误，结果所有包都 `Unable to locate package`，白跑一轮。把宿主机的 CA bundle 复制进镜像才解决。

VA-API 这边，机器上已有 Intel 的 kobuk PPA（libva 2.24 + iHD 驱动 26.3.5，Arrow Lake 要靠它），这个源 USTC 没有镜像，保留原样。驱动版本是硬解能不能跑的关键，`vainfo` 先验一遍：

```console
$ vainfo
libva info: Trying to open /usr/lib/x86_64-linux-gnu/dri/iHD_drv_video.so
vainfo: Driver version: Intel iHD driver for Intel(R) Gen Graphics - 26.3.5 ()
      VAProfileH264Main  : VAEntrypointVLD      ← 共 24 个解码入口
```

## 编译与打包：实测时长

configure 打开硬件加速开关：

```bash
./configure --prefix=/usr/local --enable-libva --enable-vdpau
# checking for LIBVA... yes    checking for LIBVA_DRM... yes
# checking for LIBVA_X11... yes    checking for VDPAU... yes
```

各阶段实测（14 核，文件时间戳测量）：

| 阶段 | 耗时 | 备注 |
|---|---|---|
| 下载源码 27.6 MB | 8.9 s | USTC IPv6 |
| 构建 Docker 镜像（装 ~300 个依赖） | **9 分 42 秒** | 一次性，之后全程复用 |
| `configure` | 14 s | |
| **`make -j14` 全量编译 380 个插件** | **56 秒** | |
| `make install` → staging | 33 s | |
| 匿名化重建全流程（后述） | **99 秒** | configure + make + install |

LLM 最初给我的预估是「约 10 分钟」，指的是重建一次的时间；实测 99 秒。**估算把一次性成本和边际成本混在一起了**——真正常驻的开销是那个 9 分 42 秒的镜像，编译本体连一分钟都不到。

打包成 deb 才是重头戏，两个设计让它像系统包一样干净：

1. **`Depends` 不靠拍脑袋**：对 staging 里的全部共享库与可执行文件（392 个）跑 `ldd`，把每个实际链接的库映射回 dpkg 包名，算出 236 项依赖；
2. **`Conflicts`/`Replaces` 覆盖官版整套 16 个包**（`vlc`、`vlc-bin`、`libvlc5`、全部 `vlc-plugin-*`……），于是 `sudo apt install ./vlc_3.0.24-1_amd64.deb` 一条命令就是**替换**，apt 记录保持一致，之后 `apt remove vlc` 照常能管。

这里遇到全场最绕的依赖链：Ubuntu 的 `phonon4qt5` **硬依赖** `phonon4qt5-backend-vlc | phonon4qt5-backend`，后者又依赖被我们干掉的 `vlc-plugin-base`——连锁反应会把 **okular 一起卸掉**。解法是同一句 apt 命令里补一个替代后端：

```bash
sudo apt install ./vlc_3.0.24-1_amd64.deb phonon4qt5-backend-gstreamer
```

模拟安装（`apt -s`）确认 okular 不受影响后才动手。apt 版 16 个包卸得零残留。

## 硬件加速验证：日志见实锤，外加一次翻车

验收标准不是「configure 通过」，而是解码日志。跑一段 H.264，`-vvv` 抓到完整证据链：

```console
avcodec decoder debug: available hardware decoder output format 44 (vaapi)
main generic debug: using hw decoder module "vaapi_drm"
[AVHWDeviceContext] VAAPI driver: Intel iHD driver for Intel(R) Gen Graphics - 26.3.5 ().
avcodec decoder: Using Intel iHD driver for Intel(R) Gen Graphics - 26.3.5 () for hardware decoding
```

对照组（`--avcodec-hw=none`）这行出现 0 次，证明它真的来自硬件路径。

翻车也要记一笔：我先用 `--vout dummy` 做无头测试，默认参数下却得到 `no hw decoder modules matched`，一度以为硬解没编进去。实际是**测试方法制造的假象**——VLC 的 VAAPI 有 X11 / DRM 两条后端，X11 后端要求 vout 提供 VA 表面（dummy vout 给不了），而默认的 `any` 只会选 score > 0 的模块。换成真实 GUI 窗口播放，默认设置一切正常。**无头环境测出来的「坏了」，得回到真实场景复验**。

## 发布前的收尾：匿名化与 GPL

准备发到 GitHub 时发现 `vlc --version` 的输出里嵌着编译机的主机名和我的用户名（configure 阶段 `hostname -f` / `whoami` 烧进去的）。查了下 `configure.ac`，两个值都支持环境变量覆盖，不用改任何源码：

```bash
VLC_COMPILE_HOST=build-host VLC_COMPILE_BY=builder ./configure ...
```

重建一次 99 秒，全树 `grep` 确认无残留，发布版显示 `Compiled by builder on build-host`。

GPL 合规方面：二进制必须能对应到源码，所以 Release 里直接附上了那份 sha256 与官方一致的原始 tarball（未打任何补丁），README 写明 configure 参数与 unofficial 免责声明（VLC 是 VideoLAN 的商标）。


仓库里有完整构建脚本（含实际使用的 USTC IPv6 版 Dockerfile），可复现。

## 小结

让 LLM 编译这件事，成立的前提是**验收标准在人手里**：校验和对官方、硬解日志见实锤、模拟安装确认无副作用、发布物扫过隐私。至于估时——这次它给我打了对折，我把两个数字都如实记在这儿。
